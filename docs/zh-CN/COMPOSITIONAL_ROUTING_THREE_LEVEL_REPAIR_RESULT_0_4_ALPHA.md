# 组合式路由三级修复结果（0.4 Alpha）

## 当前结论

最新本地候选版本修复了这轮已披露仓库复验中确认的三个具体问题。最终 13 文件任务精确选中 13 个目标文件，没有漏项，也没有额外文件。

这属于观察结果后的自审复验，不是新的盲测，不能覆盖或改写已经冻结的 Round 19 正式结果。

## 三级问题与修复

### 一级：正确性问题

词法归一化曾把单数 `status` 错误处理成 `statu`，导致任务明确要求 storage status 时仍可能漏掉对应实现。现在会保留 `status`，并把 `statuses` 归一为 `status`，同时加入回归测试。

### 二级：组合任务的召回与聚焦

原本的近邻匹配过于宽松，会把历史 `disclosed` 研究测试误认成任务明确要求的回归测试，抢走 lexical 测试与当前 verifier 的名额；同一个 router 概念也可能重复占用多个实现名额。

本轮修复包括：

- 对明确列在 `regressions`、`tests` 或 `specs` 前面的概念给予更强证据；
- 存在明确测试概念时，按这些概念计算测试配额；
- 在保留 verifier 名额前停止补入一般测试；
- 对实现关注点做概念族去重，同时保留任务明确要求的 planner 与 scorer 双关注点；
- 当前 verifier 优先于历史测试产物。

### 三级：兼容性与工程清理

第一次修复曾把 `release-routing.test.ts` 和 `router.test.ts` 合并成同一个 route 概念，造成旧回归失败。现在会保留任务明确写出的复合测试模块名称。所有临时诊断日志也已删除。
