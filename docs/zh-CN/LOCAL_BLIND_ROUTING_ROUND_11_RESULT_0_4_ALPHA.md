# 本地盲选路由 Round 11 结果（0.4 Alpha）

## 结论

Round 11 是一轮有效、完整、候选 held-out 的配对静态路由研究。8 个目标与 32 次正式观察全部完成；没有环境或 setup 失败、研究工具 contract 失败、陈旧索引、evaluate/context 路线分歧、selected/excluded 重叠，也没有修改目标仓库的 tracked 文件。

候选提高了改动文件召回率与通过目标数，但**没有通过冻结的绝对门**，因此不能进入端到端 Agent A/B。本结果只证明静态路由表现，不能证明 Agent 正确率、回报 Token 节省、Agent 工具调用减少或 Agent 执行时间下降。

## 产品失败类型

1. **公开 API contract 未闭合。** JavaScript 实现没有扩展到公开类型声明及其 declaration test。
2. **多实现文件过早饱和。** 找到一组实现和测试后，就把证据判断为足够，未继续检查同概念 producer 与 connector。
3. **Fallback 语言聚焦测试发现不足。** Rust 方法新增任务被大量泛用模块和词汇相邻测试挤占，真正 integration test 未入选。
4. **置信度与停止耦合不安全。** 尚未证明任务主题覆盖所有因果参与者，就以高置信度进入窄模式并执行停止。
5. **召回提升但聚焦不足。** 多个通过目标依靠填满路线预算才补齐证据，造成 payload 与时间增加。

## 后续研发方向

下一步必须修通用机制，而不是写仓库名称特例：加强 contract、ownership 与任务主题证据闭合；只有出现独立完整性锚点时，`route-lite` 才能强制停止；同时先为聚焦测试保留路线预算，再接纳泛用邻居。三个失败目标从现在起只能作为 disclosed regression。新的泛化证明必须来自下一轮递归排除旧仓库的 held-out 目标。
