# 0.4 Alpha 多表面路由研究

## 结论边界

这一阶段使用合成仓库与固定 changed-file oracle 评估路线选择。它没有执行完整的
Codex Agent 任务，也不能证明 reported tokens、总时间或工具调用已经下降。这里的
结果只说明路线覆盖率与相关度发生了什么变化。

机器证据：
[advisory-multi-surface-routing-0.4-alpha.json](../research/evidence/advisory-multi-surface-routing-0.4-alpha.json)

基线产品提交：`72d1ffe3deaa2f2847d669b93e01e87ee6337453`

## 为什么进行这一阶段

上一阶段的 advisory-safety 实现实际改动了 18 个文件，但 Palace 完成后的自评只命中
两个核心实现文件，changed-file coverage 为 `2/18`。共享类型、聚焦测试、中英文记录、
发布验证脚本、测试配置与重新生成的 MCP 产物都没有被找到。这个真实结果是本阶段的
起因，但不能直接与下面较小的合成 oracle 做数值比较。

## 固定任务与 oracle

夹具固定使用同一个任务，要求同时处理 mode selection、context packing、共享契约、
聚焦测试、中英文研究文档、发布验证脚本、测试配置与生成的 MCP 产物。

Oracle 固定为横跨这些职责的 11 个文件。仓库另外放入旧研究文档、无关 verify/smoke
脚本、仅用于 integration 的测试配置、泛化 router 测试，以及 tsup provenance 配置作为
竞争候选。路线限制保持 12，不能靠打开整个夹具通过测试。

## 结果

| 阶段 | 命中 | 路线文件 | Coverage | Focus | Confidence | 主要错误 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 初始失败测试 | 9/11 | 12 | 0.82 | 0.75 | 未记录 | 漏掉测试配置与一条明确要求的验证脚本 |
| 最终 | 11/11 | 12 | 1.00 | 0.92 | 0.35 | 仍多带一份旧研究文档 |

最终路线保留了两个实现概念、两个聚焦测试、两条明确要求的验证脚本、共享契约、
测试执行器配置、英文与简体中文配对文档，以及生成的 MCP bundle。唯一多带的文件是
一份历史研究文档。

宽任务的 confidence 仍被保守封顶为 `0.35`。相对本次 oracle，它低估了 `0.65`，所以
这一阶段只说明选择结果改善，不代表 confidence calibration 已经解决。

## 真实仓库自评

随后使用刚完成 build 的 CLI，对这一阶段实际改动的七个文件进行自评。这是与合成夹具
分开的第二组 oracle。

| 迭代 | 命中 | 路线文件 | Coverage | Focus | 漏掉文件 |
| --- | ---: | ---: | ---: | ---: | --- |
| 职责容量分配 | 6/7 | 12 | 0.86 | 0.50 | 当前英文报告 |
| 当前双语文档配对 | 6/7 | 12 | 0.86 | 0.50 | `publication-intent.ts` |
| 明确实现概念优先 | 7/7 | 12 | 1.00 | 0.58 | 无 |

最终路线找到了所有实际改动的实现、测试、文档、机器证据与生成物。它仍多带五个文件，
包括旧的 0.3.0 报告、旧证据，以及三个相关 router 模块。召回目标已经完成，精度则是
下一阶段要解决的问题。

最终静态 pack 估算为 3,804 tokens，仓库索引文本估算为 227,958 tokens，缩减 98.3%。
这些只是 scanner 与 pack 的静态计数，不是 Agent 实际消耗或计费数据。

## 产品修改

- 多概念实现任务按概念保留有限容量。
- 直接回归测试与任务明确要求的验证脚本使用不同配额，verify/smoke 不再挤掉聚焦测试。
- 验证脚本先保证角色多样性，再用任务与路径的词项关联排序。
- 任务明确要求测试配置时，测试执行器配置优先于无关构建配置。
- 双语文档保留英文与本地化版本配对，并优先选择同名文件。
- 表面晋升时保留已经通过 `changed_with`、`configures` 等关系取得的 provenance 理由。
- “发布验证脚本”只表示引用一个产物；除非任务同时明确要求 npm、registry、tag 或版本动作，
  否则不会被当成正式发布。

## 验证与剩余工作

聚焦 router 测试通过 `30/30`。完整工作区通过 `109/109`：core 105、CLI 2、MCP 2。
TypeScript 类型检查、lint、build、10-tool MCP smoke 与干净 release-candidate 验证也全部通过。

下一道关卡是在不损失 `7/7` 召回的前提下减少 route-only sibling，然后增加跨仓库夹具，
并根据真实覆盖率校准宽任务 confidence。静态路线改善仍不能被宣传成端到端 Agent 加速。
