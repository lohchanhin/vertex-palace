# Room Inventory 0.5：第四阶段证据面规划协议

状态：开发协议与合成人工真值已在候选观察前冻结。

## 研究问题

Vertex Palace 能否把复合任务中的明确义务转换为有界证据面，再利用文件关系与 Room Inventory 对象关系补齐这些证据面，同时不加入仓库专用规则？

Phase 3 已在披露的合成夹具上建立准确对象关系，但修复后的自仓库评估显示，广域任务仍未优于稳定 0.4：两种条件的核心覆盖率都是 `0.167`、路由聚焦度都是 `0.20`，并且都以 `0.68` 置信度呈现 overconfident。Phase 4 研究缺失的规划层，不继续增加解析器或关系例外。

## 机制边界

现有公开 `EvidenceRole` 词汇保持不变。Phase 4 可以增加内部任务级 facet 表示，但证据面必须来自明确任务子句与已索引证据：

- 实现证据面表示任务点名的行为或实现参与者。
- 约束证据面表示明确的保留或兼容义务。
- 只有任务明确要求聚焦测试，或任务类型本身要求验证时，才建立验证证据面。
- 只有任务明确要求重建、同步或保留生成输出时，才建立生成产物证据面。
- parser、compatibility、serializer、transport、adapter 等词只是任务动态生成的 facet 标签，不成为仓库专用永久角色。

`fix`、`update`、`change`、`test`、`project` 等通用动作词不能独立建立实现证据面。

## 有界规划规则

1. 从置信度最高的实现对象或文件开始。
2. 移除动作词并完成词法规范化后，每个不同的明确任务子句形成一个义务。
3. 只有已选来源的索引文本、对象身份或因果关系能够支持该义务时，才视为覆盖。
4. 只允许沿 `imports`、`calls`、`tests`、`tested_by`、`configures`、`changed_with` 或 `depends_on` 扩张，最多两个来源级 hop。
5. 每个未覆盖证据面最多加入一个来源；生成证据面为了建立 provenance，最多加入一个生成器/配置来源和一个生成输出。
6. 候选统一使用 Phase 2 已登记公式：`0.45 taskAffinity + 0.30 relationStrength + 0.25 facetGain - 0.20 degreePenalty - 0.25 redundancy`。
7. 所有明确证据面闭合，或最佳剩余增益低于 `0.55` 时停止。
8. 高连接度文件不能只因关系多而进入；来源必须补足缺失证据面，或同时满足任务相关度 `>=0.65` 与关系强度 `>=0.75`。
9. 闭合不完整时保持 advisory 并限制置信度，不能强制提前停止。
10. 产品代码禁止包含夹具路径、目标 ID、仓库名、issue 编号或语言专用预期文件名。

## 开发门槛

首次披露观察只有在所有门槛通过时才算通过：

1. 四个任务全部返回 `decision: route`。
2. 宏观必需文件覆盖率至少 `0.90`。
3. 每个目标的必需文件覆盖率至少 `0.80`。
4. 每个目标的所有明确证据面全部闭合。
5. 聚焦验证覆盖率为 `1.00`。
6. TypeScript 目标的生成产物覆盖率为 `1.00`。
7. 宏观路由聚焦度至少 `0.70`，每个目标至少 `0.60`。
8. 禁止 decoy 命中为零。
9. 重复路线一致率为 `1.00`。
10. 路线不得超过冻结文件上限或 6,000 估算上下文 Token。
11. 错误强制停止与过度自信的不完整路线为零。
12. 默认关闭的索引与路由行为保持稳定 0.4 兼容。

## 失败政策

首次观察不可修改。观察后不得修改任务文本、oracle 文件、decoy、哈希、路线限制或阈值。每类失败最多允许一次通用机制修复；失败夹具只能成为回归证据，不能作为发布资格证据。

同类失败在一次通用修复后再次出现，就暂停实现并进入架构复审。禁止加入夹具专用规则。

## 与 Round 26 的关系

Phase 4 是已披露的合成开发证据，与已经冻结的 Round 26 协议分开。Phase 4 通过不算全新目标，也不能让 `0.5.0-alpha.1` 或稳定 0.5 获得资格。只有候选产物冻结后，才能开始 Round 26 目标选择。

## 声明边界

本协议只能评价有界静态路由闭合，不能证明节省 Token、减少工具调用、更快完成或提高端到端 Agent 正确率。开发期间 npm `latest` 继续停留在 0.4。
