# 递归路线泛化回归协议（0.4 Alpha）

## 研究问题

产品候选版本 `716a6c4e2abb6432d59a17db14a940e90918fe2b` 能否同时做到：保留原有真实仓库路线；区分旧研究资料家族与其递归后继家族；精确覆盖复合产品修复；并在指定资料家族不存在时主动降低信心？

这是预注册的**已观察目标静态路由回归**，不是未见目标验证，也不是端到端 Agent 性能实验。因此，它不能证明 Agent 节省 Token 或缩短执行时间。

## 冻结实现

- 产品提交：`716a6c4e2abb6432d59a17db14a940e90918fe2b`
- 验证器：`scripts/verify-recursive-route-generalization.cjs`
- 证据路径：`docs/research/evidence/recursive-route-generalization-regression-0.4-alpha.json`
- 验证器提交是包含本协议的预注册提交，并会自动记录在证据中。
- 构建前后都会逐项比较产品路径与冻结产品提交。
- 证据文件使用只允许新建的写入方式，第二次执行不能覆盖第一次正式观察。

## 冻结目标

外部回归继续使用先前实验中已经固定的 Zod、Requests 和 p-limit 仓库、提交、任务、实际改动文件与可接受路线边界。

候选版本自我审核在首次正式执行前固定以下七个目标：

1. 原始跨仓库资料家族，英文任务。
2. 原始跨仓库资料家族，简体中文任务。
3. post-self-audit 递归资料家族，英文任务。
4. post-self-audit 递归资料家族，简体中文任务。
5. 七文件的生成产物新鲜度与复合路由修复。
6. 七文件的 release 词汇动作分类修复。
7. 不存在的 Cobalt Harbor 资料家族，作为低信心负对照。

任务文本、实际改动文件、可接受文件和门槛全部以常量写入验证器，并在执行前提交。

## 固定执行方式

- 每个目标重复两次。
- 路线文件上限：9。
- 上下文预算：6,000 个估算 Token。
- 最多加载 4 个 drawer。
- 外部仓库按固定提交下载到互相隔离的临时目录。
- 候选版本审核使用冻结产品提交的 detached clone。
- 将当前构建的 CLI 复制到候选 clone，作为已声明但被忽略的生成产物。
- 在第一个候选目标前明确执行初始化与索引。
- 所有目标依次执行，不并发运行。

## 通过门槛

- 每条路线在两次重复中完全一致。
- Zod、Requests、p-limit 的改动文件覆盖率和可接受路线精确率均为 1.00。
- 新旧资料家族的中英文任务均达到 1.00 覆盖率、至少 0.85 focus、最多七个路线文件及 1.00 可接受路线精确率。
- 两项产品修复均达到 1.00 覆盖率、1.00 focus、最多七个路线文件及 1.00 可接受路线精确率。
- 不存在资料家族的预期覆盖率为 0.00，confidence 不得高于 0.15；因为目标文件并不存在，这才是安全行为。
- 已完成路线不得相对于实际覆盖率表现为过度自信。
- 每个自适应上下文 payload 不超过 6,000 个估算 Token。
- selected 与 excluded 执行边界不得重叠。
- Palace 不得修改任何目标仓库的 tracked 文件。
- 候选版本明确索引后必须立即显示 `stale: false`。

任何命令失败、重复不完整、门槛未达、边界冲突、tracked 工作树变脏或路线不一致，都会使整个研究失败。环境错误也必须保留在原始证据中，不能静默删除。

## 报告规则

第一次 JSON 观察将原样保存并计算哈希。英文与简体中文结果报告必须明确区分：

- 产品验证与 Agent 性能；
- 已观察目标回归与真正未见目标泛化；
- 预期的负对照未命中与错误的高 confidence；
- 产品失败与环境失败。

不得只挑选有利子集取代完整预注册结果。
