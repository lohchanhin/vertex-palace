# Room Inventory 0.5：第三阶段关系质量协议

状态：候选执行前已冻结。

## 研究问题

第二阶段证明了精确对象身份可以把一个 symbol 排到第一，但已披露的宽任务自评并没有改善多文件任务闭合。第三阶段改问一个更窄的因果问题：推断出的 `contains`、`calls`、`tests`、`tested_by` 是否准确、是否足够完整、是否确定，而且在关闭 Room Inventory 时是否完全不存在？

本协议在运行 0.5 候选前冻结答案。它是合成开发研究，不是 Round 26 资格结果。

## 冻结夹具

夹具包含 TypeScript、JavaScript、Python、Go、Rust 共 11 个源码文件。每种语言都提供：

- 一条唯一的实现到实现调用。
- 一条聚焦测试到实现关系，以及反向 `tested_by` 关系。
- 两个同名歧义目标，工具不得猜测。
- 在 Phase 0 解析契约已能表达 Owner 的语言中，提供一条 Owner 到成员的 `contains` 关系。Phase 0 对 Rust 只冻结了函数对象，因此本夹具不声明 Rust Owner 真值。

oracle 一共包含 27 条应有关系和 10 条禁止的歧义关系。它既包含歧义控制对象正确的 Owner 到成员结构，也继续禁止 caller 猜测同名目标。未声明但被推断出的关系先交由人工审核，不会自动算成误连。

在候选执行前，协议审计补入了 8 条有效的 Owner 到歧义成员 `contains` 关系，使已声明端点的精确率真值完整。这个观察前修订已写入机器可读协议；当时尚未运行候选。

## 标准测试约定

冻结测试面使用一般生态约定，不使用工具专用命名：

- TypeScript：`*.test.ts`
- JavaScript：`*.test.js`
- Python：`tests/test_*.py`
- Go：`*_test.go` 与 `TestXxx`
- Rust：`#[test]`

如果首次观察遗漏其中一种约定，失败结果必须保留。针对同一失败类别最多进行一次语言通用的测试识别修复，不能修改 oracle 或阈值。

## 指标与门槛

- 对象端点解析率：`1.00`
- 宏观关系精确率：至少 `0.95`
- 宏观关系召回率：至少 `0.80`
- 单语言关系召回率：至少 `0.50`
- 测试闭合召回率：至少 `0.80`
- 禁止关系发生率：必须为 `0`
- 重复索引关系一致率：`1.00`
- 单对象最大出边：`32`
- 默认关闭时对象关系数：`0`

无法解析的应有关系计为漏失。精确率只统计 oracle 已声明端点之间的推断关系；未声明但可能合理的关系需要人工审核。

## 执行顺序

1. 先提交并推送本协议、夹具、oracle、哈希与守卫测试。
2. 执行一次默认关闭条件。
3. 执行两次开启条件，并比较确定性关系键。
4. 完整写入首次观察，不修改夹具、oracle 或阈值。
5. 如果门槛失败，同一失败类别最多允许一次通用机制修复。
6. 使用同一份不可修改夹具重跑，并把结果标记为已披露修复。

生产路由规则不得出现仓库名、夹具 ID、对象名或预期路径。

## 声明边界

即使第三阶段通过，也只能证明冻结夹具上的合成关系质量，不能证明全新 Round 26 资格、节省 Token、减少工具调用、加快完成或提高端到端 Agent 正确率。
