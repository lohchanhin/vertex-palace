# 本地盲测路由目标选择协议（0.4 Alpha，第 17 轮）

## 状态

32 个仓库的 URL 计划已在任何第 17 轮 HEAD 查询前完成本地冻结。仓库池、目标选择与
静态验证尚未开始；只有相互匹配的 create-only 冻结清单和完整性测试才能授权执行。
目前没有查看任何第 17 轮历史、commit subject、diff、任务、语义审核、oracle 或 Palace
结果。

这是可检查篡改的本地协议，不是公开预注册。比赛冻结仍然禁止 commit、push、tag、npm
发布以及修改已提交的参赛材料。

## 为什么需要第 17 轮

第 16 轮在语义审核前停止，因为固定的每类 4 个候选仓库中，Rust 只有 1 个仓库产生机械
合格候选，无法填满每类 2 个目标的固定配额。该结果已原样保留，不得重写。它不能说明
产品好坏，却证明目标选择协议的 fallback 容量不足。

第 17 轮只改变暴露任务内容前的候选容量：每个语言家族由 4 个仓库扩大为 8 个。最终样本
仍是 8 个目标、每类 2 个；所有产品质量门槛完全不变。扩大候选池的决定发生在任何第 17
轮 HEAD 查询或任务内容被查看之前。

已完成的真实仓库 v4 Agent 研究仍是产品基线：Adaptive 严格成功 3/16，Control 严格成功
11/16。第 17 轮只是本地 0.4 候选版的新鲜静态确认门，本身不能证明 Agent 正确性或效率。

## 研究问题

在未见、任务一致的真实历史变更上，冻结的 0.4 候选能否找回必要实现与聚焦验证证据，
同时避免无关扩张、不安全停止与没有依据的高置信度？

优先级固定如下：

1. 任务类型正确；
2. 实现与聚焦验证完整；
3. changed-file coverage 与 route focus；
4. 置信度校准和安全的 advisory 行为；
5. context 保持有界；
6. 静态命令耗时。

较小 payload 不能补偿必要证据缺失。

## 独立性边界

计划递归排除了截至第 16 轮已经观察过的全部 178 个仓库。仓库池冻结前唯一允许的网络
操作是：

```text
git ls-remote <repository-url> HEAD
```

URL+HEAD 仓库池产生前，不得 clone、fetch、遍历历史、读取 subject 或 diff、构造任务、
语义审核、构造 oracle，也不得对候选任务调用 Palace。

## 仓库平衡

- 32 个仓库，采用固定交错顺序。
- JavaScript/TypeScript、Python、Go、Rust 各 8 个。
- 每个语言家族接受 2 个目标，后续仓库作为 fallback。
- 最终总共选择 8 个目标。
- 每次仓库尝试与拒绝都保留在审计记录中。
- 某语言家族填满 2 个目标后立即停止查看该家族的后续仓库。

仓库知名度不是结果。仓库名称只在递归排除检查后确定，没有使用任何第 17 轮任务内容。

## 候选选择

候选源码、CLI、生成的 MCP、选择器、协议、完整性测试和比较基线全部通过 SHA-256 冻结后：

1. 每个仓库最多检查 300 个非 merge commit；
2. 最多保留 5 个机械合格候选，按时间从新到旧；
3. 要求单一 parent、20-180 字符行为 subject、2-8 个已存在修改文件、至少一个实现文件和
   一个聚焦测试、最多两个辅助文件、2-400 行改动；
4. 生成完整 unified-zero diff 与 hunk-addressed 审核包；
5. 每个 hunk 只能标为 task-aligned、unrelated 或 uncertain；
6. 任一 hunk 为 unrelated 或 uncertain 时拒绝整个目标；
7. 禁止 partial oracle pruning；
8. 每个仓库接受最新的任务一致候选；
9. 在仓库接受点与语言家族配额边界停止。

语义审核完成前，对候选任务的 Palace 调用必须保持为 0。生成文件只有在 owning generator
同时位于相同 oracle 中时才可纳入，而且整轮最多一个 generated-artifact 目标。

## 审核者限制

研究由一个获得开发者授权、使用 Codex 协助的语义审核者，加上机器完整性验证来完成。
审核者并不独立于产品开发，也没有第二位人类审核者或 inter-rater agreement。歧义必须
保守拒绝。机器验证只能证明审核包完整与顺序正确，不能证明语义判断本身必然正确。

## 冻结静态门槛

候选版本绝对门要求：

- 8/8 目标完成且结果确定；
- 8/8 任务类型正确；
- 8/8 实现与聚焦验证表面完整；
- 所有预注册且执行或验证所需的辅助表面完整；
- macro changed-file coverage 至少 0.90；
- macro route focus 至少 0.70；
- 每个目标 coverage 至少 0.50、focus 至少 0.40；
- 过度自信 trial 为 0；
- 不安全窄模式与不安全强制停止为 0；
- context/evaluation 路线不一致与指标不一致为 0；
- 所有 context 都不超过 6,000 estimated Tokens；
- 目标 worktree 没有 tracked 修改。

只有冻结语义审核认定为执行或验证任务所必需时，辅助文档或 changelog 才计入门槛。
历史 diff recall 不能强迫产品路线加入泛用文档。

公开的 0.3.0 产品只作为描述性基线。相对基线改善不能覆盖绝对门失败。

## 前进规则

只有有效且新鲜的第 17 轮绝对通过，才可授权另行冻结的 v5 Agent A/B 协议，并且必须使用
新的 issue 身份与 trial ID。若失败，原始失败必须保持不可改写，后续只能依据失败类别进行
与仓库无关的产品优化。第 13-15 轮事后修复和第 16 轮选择失败都不能替代新鲜确认。

这项静态研究不能证明 Agent 正确率、Token 节省、工具调用减少或 wall time 下降。
