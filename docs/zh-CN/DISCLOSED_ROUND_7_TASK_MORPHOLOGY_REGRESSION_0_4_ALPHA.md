## 解读

1. `Fixes`、`Avoid`、`Prevents` 等开头动词变化确实是产品分类缺陷，目前已经由产品测试覆盖。
2. 分类并不是 Round 7 路由失败的直接原因；修正分类后，没有多命中任何文件。
3. Execa 改成 bugfix 后仍以 `0.75` 过度自信，Mio 仍为 `0.86`。这说明核心配对产生的 confidence cap 会盖过薄弱或错误的直接证据。
4. 下一项修复必须进入证据选择层：辨别同模块的实现与测试镜像、允许文字证据稀疏但结构证据强的测试进入配对，并要求实现文件具有独立任务证据后才能给高置信度。

## 声明边界

这项修复只改善任务类型语义，没有改善这组已披露样本的静态路由结果，也不能证明 Vertex Palace 节省 Token 或时间。
