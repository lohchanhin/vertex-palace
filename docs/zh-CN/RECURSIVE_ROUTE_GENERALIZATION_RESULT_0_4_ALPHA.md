# 递归路线泛化回归结果（0.4 Alpha）

## 结果

**失败。** 产品候选版本 `716a6c4e2abb6432d59a17db14a940e90918fe2b` 保住了三个固定外部仓库，并通过候选版本审核的七个目标中的六个；但是，简体中文递归资料家族目标在两次重复中都失败。

因此，这个候选版本**不能进入 held-out 未见目标测试**。本研究只是已观察目标的静态路由回归，不能证明 Agent 节省 Token 或缩短执行时间。

## 失败细节

简体中文递归任务的两次 trial 都选中了完整的旧 `CROSS_REPOSITORY_ROUTE_PRECISION_*` 家族以及 `tsconfig.base.json`，六个目标 `ROUTE_PRECISION_AFTER_SELF_AUDIT_*` 文件一个都没有选中。

两次重复的结果完全一致：

- 改动文件覆盖率：`0.00`；
- route focus：`0.00`；
- 可接受路线精确率：`0.143`，只有 `tsconfig.base.json` 位于冻结边界内；
- confidence：`0.77`；
- 校准：过度自信，误差 `0.77`。

包含同一个 `post-self-audit` 身份的英文任务能够选择正确递归家族；旧资料家族的英文与简体中文任务也都正确。因此，这不是全面的中文解析失败，也不是环境问题。当前观察到的缺陷更窄：简体中文句子结构与嵌入式递归家族身份组合时发生误选。

目前的工作假设是：资料家族亲和力流程没有在中文任务分析中充分保留嵌入的 `post-self-audit` 身份，使通用跨仓库旧家族胜出。这仍是需要测试的推论，不是已经确认的根因。

## 负对照

不存在的 Cobalt Harbor 家族预期就是零目标文件覆盖率。两次 trial 的路线 confidence 都被限制为 `0.15`，并维持良好校准，因此这项门槛通过，证明冻结的英文负对照能够触发缺失家族信心上限。

但这不能抵消中文失败：中文目标指定的资料家族真实存在，因此零覆盖时仍给出 `0.77` confidence 是不安全的。

## 决策

不把候选版本 `716a6c4` 推进 held-out 测试，也不重跑或覆盖本研究。

下一个开发候选版本必须：

1. 用完全相同的简体中文递归任务建立聚焦单元回归。
2. 检查任务实体与资料身份 Token，确认 `post-self-audit` 在哪里丢失或权重不足。
3. 支持嵌入中文句子的复合家族身份，同时避免增加语言专用文件名特例。
4. 当双语任务要求的家族身份无法解析时，也要触发低 confidence 行为。
5. 保留所有外部仓库、英文、产品路线、新鲜度、确定性路线及负对照门槛。
6. 冻结新的产品提交，并在观察正式结果前预注册新的后续研究。

只有后续研究通过，才选择真正未观察过的仓库和任务进行 held-out 验证。
