# 本地盲测路由目标选择协议（0.4 Alpha，第 9 轮）

## 状态与结论边界

本协议在读取任何第 9 轮仓库历史、提交标题、差异、任务或 Vertex Palace
输出之前完成本地冻结。冻结前只通过 `git ls-remote <url> HEAD` 取得仓库网址
与 HEAD 对象编号。

比赛结果公布前，目前禁止提交或推送产品与研究改动。因此本轮不使用 Git
commit 作为预注册凭证，而是由本地冻结清单记录英文协议、简体中文协议、仓库
池、选择器、分类器、候选 CLI 与基线 CLI 的 SHA-256。选择器会重新验证全部
摘要，并且结果文件只能建立一次。

这足以辅助内部研发判断，但**不属于公开预注册**，不能用来宣称外部泛化。
比赛冻结解除后，任何准备公开的确认实验都必须换用全新仓库池，并在选择目标
前先提交协议。

## 已保存的第 1 次尝试与基础设施修订

第 1 次选择在检查冻结的 `rand` 仓库时停止。partial clone 需要补取 promisor
object，当时 GitHub DNS 解析失败。没有任务文字被输出或交给 Palace，没有产生
目标 manifest，产品内容也与冻结哈希完全一致。失败证据保存在
`docs/research/evidence/local-blind-routing-target-selection-round-9-attempt-1-failure.json`。

第 2 次尝试以前，只允许三项 harness 修订：完整取得冻结的浅层历史、逐仓库捕获
inspection error，以及把未预期异常写成 create-only 证据。产品、仓库池、顺序、
合格规则、任务分类器、配额与指标都没有改变；修订后的文件会先建立新的本地哈希
冻结，再重新执行选择。

## 研究问题

在再次投入昂贵的端到端 Agent 实验之前，当前本地 0.4 候选是否能在新的真实
仓库任务中，比优化前基线更可靠地找齐实现、聚焦测试与受限辅助证据，同时保持
路线聚焦和上下文受控？

固定判断顺序如下：

1. 任务类型正确；
2. changed-file 与因果证据覆盖；
3. 路由聚焦度与精确率；
4. 置信度校准与模式安全；
5. 实际投放 payload；
6. 静态命令耗时。

缺少必要证据时，payload 较小不算优势。

## 冻结产品

本地冻结清单会绑定：

- 基线提交 `67c0a2ce8754cece3773d5fd16b89dae4e3af0c1`；
- 离线重建的基线 `dist/palace.cjs` 摘要；
- 当前本地构建候选 `dist/palace.cjs` 摘要；
- 候选源码树及生成后 MCP bundle 的摘要；
- 本协议、英文版、仓库池、选择器、任务分类器与文件表面分类器。

任何摘要不一致都必须中止选择或验证。冻结后，在保存第一个第 9 轮结果以前，
不得修改产品代码。

## 完整排除边界

排除集合由冻结的第 8 轮仓库池机械生成：

- 第 8 轮以前所有已观察仓库；
- 第 8 轮的 16 个主选与备用仓库，无论当时是否真的检查。

合并后应有 97 个不重复仓库网址。第 9 轮另外使用 16 个新网址，每个语言家族
4 个。组织或生态重叠仍属于限制，最终必须披露。

## 固定仓库顺序

第 9 轮选择 8 个目标，JavaScript/TypeScript、Python、Go、Rust 各 2 个。
仓库池依语言交错排列。每个家族最先出现的两个合格仓库胜出；配额填满后，
该家族后续备用仓库不再读取。

## 机械任务选择

每个被检查的仓库最多扫描最近 300 个非 merge commit，并选择最新的合格提交。
规则与第 8 轮一致：

1. 只有一个 parent；
2. 未改写的第一行标题长度为 20 至 180 字符，并能由冻结分类器判断任务类型；
3. diff 修改 2 至 8 个文件，状态必须全部为 `M`；
4. 至少一个实现文件和一个聚焦测试文件使用该语言的冻结扩展名；
5. 最多允许两个原本已存在的文件或设定辅助文件；
6. 排除生成物、lock、vendor、fixture、snapshot、example、benchmark、build、
   coverage 与 distribution；
7. 总变更行数为 2 至 400；
8. 每个 oracle 文件在 parent 与目标提交都存在。

parent commit 是路由时状态，选中 commit 是 ground truth；未经改写的标题就是
任务，全部合格修改文件组成 changed-file oracle。选择器不存在 Palace 调用路径。

## 环境与保存规则

- Fetch 深度：400 个 commit，并完整取得该浅层历史所需对象，检查阶段不再执行
  lazy promisor fetch。
- 最多 materialize 3 次，每次间隔 5 秒。
- 环境失败时，只能进入同语言家族的下一个冻结仓库。
- 全程顺序执行。
- manifest 只能建立一次，失败也必须保留。
- 在成对验证协议与 validator 完成本地哈希冻结以前，不得把选中任务交给任何
  Palace 条件。

## 下一道门

目标选择不是产品结果。成对静态验证将让基线与候选使用完全相同的仓库和任务，
进行两次确定性重复、采用 6,000 Token 上限，并平衡 AB/BA 顺序。只有通过绝对
静态证据门，才允许建立另一份冻结的端到端 Agent 协议。静态路由本身不能证明
Agent 正确率、reported Token 节省、工具调用减少或执行时间降低。
