## 通用修复

1. 采用有边界的词形归一化，支持 `cloning -> clone`，同时避免把 `missing`、
   `parsing` 等词错误截断。
2. CommonJS 相对包根导入会经由 `package.json` 声明的入口解析，使
   `require('..')` 能把根测试连接到真正实现。
3. 包边界实现可以在只有一个明确候选时闭环到常规根级整合测试，但不会把多个
   包入口全部扩张成路由种子。
4. fallback parser 会保留长符号完整函数体中的复合字面量。位于函数后段的
   `neon-vfpv4` 因而能提供 `neon vfpv4` 的任务证据。
5. 路由专用概念归一化会把 `parser`、`parsing` 映射成 `parse`，但不会放宽
   共享词法 stemmer。
6. 诊断型 feature 任务只有在同时具备精确身份测试、两个任务命名实现模块、
   实现间因果关系及目标诊断行为时，才能提前停止在因果闭环。

## 剩余边界

- `groupcache` 不应被拿来写仓库专用规则。任务只说按 Effective Go 修正函数注释，
  并没有指出 `consistenthash`；从父提交预测该未来 diff 本身是不充分决定的。
- `cors` 不足以支持“所有 bugfix 都加入 changelog”。任务描述的是运行时行为，
  没有说明版本记录；后续应区分核心代码信心与完整 diff 信心。
- `jaraco-path` 指向下一项可泛化研发：核心闭环后，不能贡献新任务意图或因果证据
  的仓库配置与弱传递支援，应降到 Deferred。
- 这些静态指标只评估路线重叠与聚焦，不能证明 Agent 能更快、用更少 Token
  产出正确修改。
