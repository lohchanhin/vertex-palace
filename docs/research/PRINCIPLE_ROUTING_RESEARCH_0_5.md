# Vertex Palace 0.5 Principle-Level Routing Research

## Objective

Improve routing by repairing general information flow, not by adding repository names, issue numbers, paths, or one-off keyword rules.

## Four invariants

1. **Action precedence**: the requested engineering action outranks lifecycle and risk prose. A bug described as a release blocker remains a bugfix; a real publish, tag, or version action remains release work.
2. **Identity conservation**: an explicit repository path, class, method, function, endpoint, or test identity must survive scoring, surface balancing, expansion, pruning, and final truncation. Ambiguity must be reported rather than silently replaced.
3. **Bounded prose evidence**: repeated broad words in long issue bodies cannot outvote exact identities or actionable clauses. Prose adds facets; repetition does not create unlimited evidence.
4. **Observable truth**: static route recall is scored only against artifacts that exist in the indexed base commit. New files created by the hidden solution remain outcome truth and are reported separately.

## Anti-loop rules

- A disclosed target is permanently closed for tuning and becomes regression evidence only.
- Production code may not contain target repository names, issue numbers, frozen paths, or target-specific aliases.
- One failure class permits one general mechanism repair. A repeated failure after two fresh rounds triggers architecture review, not another case rule.
- Parser, classifier, router, context contract, and Agent efficiency are evaluated as separate layers.
- Token and speed claims require successful paired outputs; a failed arm is not a zero-valued measurement.

## Current hypotheses

- `releaseIntent` is too permissive because any unqualified release mention can become intent.
- Exact object recognition already works, but final selection does not enforce symbol identity as a contract.
- Hidden-diff truth currently mixes base-observable files with newly created files.

## Current evidence

- Neutral action and identity fixtures pass without repository-specific vocabulary.
- The full product suite passed with 281 core tests, 2 MCP tests, 3 CLI tests, and 274 research tests; 2 research cases remain intentionally skipped.
- On the disclosed V6 regression, the task changed from `release` to `bugfix`, and `python/djust/components/function_component.py` became the first Primary source because `RenderSlotTagHandler._render_value` was conserved.
- Illustrative values such as `content`, `value`, and `str` no longer become mandatory route identities merely because they appear in code formatting or inside a qualified method name.
- The disclosed regression delivered about 1,353 estimated context Tokens, but still took about 96 seconds and retained one noisy coordinated source. This is regression evidence only, not fresh qualification or a speed claim.
- The focused V6 test file was created by the hidden diff. The original result remains negative because the base-observable implementation was missed; future protocols must score new-file work through a preregistered observable creation surface.

## Residual work

- Bound broad prose facets so they cannot keep adding low-value support after the exact implementation anchor is secured.
- Profile context latency independently from indexing and routing quality.
- Freeze this mechanism before selecting a fresh qualification repository.

## Acceptance sequence

1. Add neutral fixtures that fail before the mechanism change.
2. Repair action precedence and exact identity conservation without target vocabulary.
3. Run focused tests, the full workspace suite, build, lint, MCP smoke, and release-candidate checks.
4. Use disclosed targets only as regression checks and publish failures unchanged.
5. Freeze the candidate, then select a mechanically fresh repository for the next qualification round.

No single historical target can qualify 0.5.
