## Generic Repairs

1. Treat the action verb `add` as task syntax instead of repository evidence.
2. When a novel feature has no lexical anchor, return one unambiguous
   conventional implementation entry and its direct test at low confidence.
3. Expand bounded behavior phrases for Python string annotations, fail-fast
   cancellation, and Apple platform families.
4. Close additive root options through type declarations and public README
   documentation when those surfaces form the external contract.
5. Close an owner-unspecified additive method through a directly related,
   same-directory API variant and its mirrored test.
6. Preserve a transitive implementation bridge when the evidence graph shows
   that selected code and verification are connected through that source file.
7. Apply workspace isolation only when every selected implementation belongs to
   the same explicit workspace; mixed root/workspace routes remain eligible for
   a root implementation bridge.
8. Keep confidence conservative when exact task-subject evidence is absent.
